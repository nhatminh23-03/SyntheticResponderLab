## The headline problem this branch fixes

The product's premise is *grounded* synthetic respondents. It was not delivering
that, and it did not say so.

Persona generation loads four ACS prior tables. **Those tables were never in the
repo, in any commit.** `persona_generator` catches the missing-file error and
silently substitutes rule-based ("heuristic") profiles. Every run reported
success while serving demo-shaped people. Two smaller paths degraded the same
way — silently substituting mock answers for real model output.

All three are now closed, and the paths that could degrade silently now fail
loudly instead.

## What changed, by commit

### `b3bd4b5` — Ground persona generation in real ACS data

The substantive commit. Review this one closely.

- **Added `apps/api/scripts/build_grounding_priors.py`** — derives the four prior
  tables from US Census ACS PUMS 2023 microdata. No API key needed (bulk files,
  ~850MB download, one-time). PUMS rather than the aggregate ACS API because the
  sampler draws *joint* rows (age × income, tenure × structure), which microdata
  carries natively.
- **Committed the four `.parquet` outputs** (~12KB total) so deploys are
  reproducible without re-running the build.
- **Dockerfile now copies the priors in and fails the build if absent**, so
  production cannot silently serve heuristic personas.
- **Fixed option matching** in `run_manager.py`. It required an exact string
  match, so `gpt-4o-mini` answering `"Moderately interested."` (trailing period)
  was rejected and replaced with a mock answer. Now matches on normalized text
  through three tiers — exact → normalized → *unambiguous* containment — while
  still rejecting genuinely ambiguous output like `"interested"`.
- **Replaced the dead `google/gemini-2.0-flash-001`** in the fallback model
  catalog; OpenRouter now 404s it.
- **Fixed an opaque 500**: `ValidationError.errors()` embeds the raising
  `ValueError` under `ctx`, which is not JSON-serializable, so a model-validator
  failure surfaced as a server error instead of a 400.
- **Fixed test isolation**: `conftest.py` leaked the developer's `.env` into the
  suite, enabling the deployment-secret middleware and 401'ing most tests. It
  also pointed at the pre-vendoring legacy path. The suite went 17 → 88 passing.

**Data validation.** The aggregates match published Census figures, which is the
evidence that the pipeline is correct rather than merely producing numbers:

| Measure | Built from PUMS | Published (ACS 2023) |
| --- | --- | --- |
| Total households | 131.3M | ~131.4M |
| Homeownership rate | 65.3% | ~65.2% |
| Single-person households | 28.8% | ~29% |
| Work from home | 13.9% of workers | ~13.8% |

### `1c99e92` — Parallel runs, default sample size 20

Each respondent is an independent provider round-trip, but they were issued
serially — roughly twelve minutes per run at the old default of 100.

- Requests now dispatch through a thread pool bounded by the new
  `SIMULATION_MAX_CONCURRENCY` (default 8, max 32).
- **Only the network calls are parallel.** Prompts are built up front and results
  are folded back in respondent order, so a run is deterministic regardless of
  completion order. A test asserts parallel and sequential runs produce
  byte-identical records.
- Default sample size 100 → 20, in both the Neo bootstrap and the experiment form.

### `ff9e36f` — Light-mode Analysis contrast + coffee demo preset

- **Contrast bug**: the Result Dashboard header and chart shells hardcoded dark
  backgrounds while their text used the theme token — dark navy on near-black in
  light mode. The light-theme override rules in `globals.css` did not cover those
  values, and two used the `[background:...]` arbitrary-property form the
  `bg-[...]` selectors cannot match at all. Fixed by using theme variables
  directly (plus one new `--theme-sticky-scrim`) rather than adding more
  substring overrides. Title contrast goes to ~9.7:1; dark mode unchanged.
- **Coffee preset**: generalized the Neo bootstrap into a `DemoPreset` registry
  and added a general-mode coffee-subscription preset with its own bundled
  32-question survey. Verified the full chain runs product-agnostically: 640/640
  live answers, and personas correctly included renters and low-income households
  that the Neo preset structurally excludes.

### `c58ca44` — Remove the coffee preset card from Study Setup

The card sat as a third item in a two-card grid and collided with the floating
next-section control. The preset itself is unchanged and still tested; it is now
API-only, which suits its purpose as a verification fixture.

### `724cc68` — Ownership: two toggles → one selector

"Homeowner Only" + "Renter Only" were independent toggles, so "include both"
looked like selecting both — which is contradictory and was rejected. Worse,
allowing it would have been silently wrong: `_sample_ownership_home_type`
branches `if/elif`, so both-true would have produced owner-only personas.

Including both is the *neither-selected* state, which the toggles gave no way to
choose deliberately. Now one selector: Any (owners and renters) / Homeowner only
/ Renter only. Any draws the real population mix — 69% owners / 31% renters
across 200 personas — not an even split.

### `c3c10f6` — AI survey generation, clipboard paste, image error fixes

- **Clipboard paste and drag-and-drop** for product images. The window-level
  paste handler ignores events aimed at a text field so it cannot steal a paste
  meant for an input.
- **Image format detection**: the upload endpoint only checked the *filename
  extension*, so a HEIC or WEBP renamed `.png` reached the vision provider and
  returned an opaque `HTTP 400`. Formats are now detected from magic bytes and
  named in the error; the data URL carries the real MIME type instead of always
  claiming `image/jpeg`; provider errors include the provider's own explanation.
- **AI survey generation** (general mode) — see below.
- **Fixed a regression from `b3bd4b5`**: FastAPI's `RequestValidationError.errors()`
  takes no keyword arguments, so the shared sanitizer raised `TypeError` and
  turned every malformed request body into a 500. No existing test covered that
  path; one does now.

## New feature: AI survey generation

In General Custom Study mode the survey step offers a generator alongside upload.

```
POST /api/v1/studies/{study_id}/survey/generate    # draft; nothing persisted
POST /api/v1/studies/{study_id}/survey/generated   # save an approved draft
```

`generate` takes `question_count` (3–60, default 20), optional `instructions`,
and `previous_schema` + `conversation` for iterative refinement, so the
researcher can keep asking for changes in a chat until the draft is right.

Design points a reviewer should check:

- **Drafts are never persisted** until explicitly accepted. Regenerating or
  discarding cannot damage a saved survey.
- **Every draft goes through the same normalizer and validator as an uploaded
  file**, so a malformed model response is a clean error, not a broken survey.
- Saved Product details are required; missing market/audience is allowed but
  reported as a warning, since it weakens the questions.
- Counts against `DAILY_PROVIDER_RUN_LIMIT` via a new `survey_generation` metric.

Verified live: generated 8 questions for an e-bike product, refined by chat to 9
including a requested $1,499 price question, and saved the result.

## Known gaps and follow-ups

Honest list of what is *not* done:

1. **Realism scorecard is permanently unavailable.** It needs
   `realism_targets_neo_smart_template.json`, which has never existed in this
   repo. The code degrades correctly and reports unavailable; the test now
   asserts that real behaviour rather than the aspirational one. This is the
   validation layer, deferred by decision.
2. **One skipped backend test** needs a proprietary `.docx` survey fixture that
   was never committed.
3. **Survey parser silently drops malformed question headers.** The id pattern is
   `[A-Za-z]?\d+[A-Za-z]?` — no underscores — so authoring `Q7_1` explicitly
   yields *nothing*, with no warning. Sub-ids only come from matrix-table
   expansion. Real users will hit this; the parser should warn.
4. **`NeoSmart-Hackathon-App/` is empty** in this checkout. The runtime is
   vendored at `apps/api/legacy_runtime/`, and the Dockerfile copies it to the
   path `LEGACY_APP_ROOT` expects. The README still describes the old layout in
   places.
5. **Backend does not verify Clerk JWTs.** Trust flows through the Next.js proxy
   plus `DEPLOYMENT_SHARED_SECRET`. Pre-existing; noted in earlier audits.
6. **Older `Documentation/audit*.md` files are stale** — they claim 64 backend
   tests passing and describe the branch as deploy-ready. That claim was not
   reproducible; the suite was broken. Treat this document as current.
